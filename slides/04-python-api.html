O que é uma API de LLM?

  • API = garçom entre seu código e o modelo
  • Você manda JSON, recebe JSON
  • Esse padrão é universal — Ollama, llama.cpp, OpenAI, todos igual

Entender HTTP = entender todas as APIs de LLM.

Chat com memória

  • Cada chamada manda o histórico completo
  • O modelo não "lembra" — recebe tudo de novo
  • É uma lista de dicts: system → user → assistant → user → ...

É como repetir toda a conversa toda vez que você fala.

Direto no motor: llama-server

llama-server \
  --port 8081 \
  --model ~/.llama-models/lfm2.5-2.6b/LFM2.5-2.6B-QAD-Q4_0.gguf \
  --fit on --fit-target 512 \
  --ctx-size 8192 \
  --jinja \
  --temp 0.1 --top-p 0.9 --top-k 50 --min-p 0.0 \
  --repeat-penalty 1.1 \
  --cache-type-k q4_0 --cache-type-v q4_0 \
  --flash-attn auto

O padrão universal: /v1/chat/completions

import requests
import json

response = requests.post(
    "http://localhost:12434/v1/chat/completions",
    json={
        "model": "lfm2.5-2.6b",
        "messages": [
            {"role": "system", "content": "..."},
            {"role": "user", "content": "O que é Python?"}
        ],
        "temperature": 0.7,
        "max_tokens": 8192
    }
)

response_dict = response.json()
print(json.dumps(response_dict, indent=2, sort_keys=True))

Um código, N servidores

requests.post(url, json=payload)
  • O payload é idêntico. O HTTP não sabe a diferença.

Ferramentas como o llama-swap trocam de modelo a quente.

Tratamento de Erros

Código Significado O que fazer
ConnectionError Servidor não existe Subir o servidor!
404 Modelo não encontrado Conferir em /api/tags
429 Rate limit Aguardar e tentar
500 Erro do servidor Conferir payload

Erro clássico: esquecer de subir o servidor antes da requisição.
