* O problema do LLM puro

LLMs são modelos de linguagem. Eles *preveem* texto, não calculam.

#+BEGIN_SRC text
Pergunta: "Quanto é 234 × 987?"
#+END_SRC

O modelo não calcula. Ele *prevê* a resposta baseado em padrões.
Pode acertar, pode errar.

* A solução: ferramentas

Ferramenta = função Python que o agente pode chamar.

[[https://colab.research.google.com/github/luksamuk/guilda-ia/blob/main/notebooks/aula06_primeira_ferramenta_colab.ipynb][📓 Colab]]

** Como funciona:
1. O LLM recebe a descrição das ferramentas disponíveis
2. Analisa a pergunta
3. Decide: preciso dessa ferramenta?
4. Gera os argumentos no formato correto
5. Python executa e devolve resultado
6. O LLM usa o resultado na resposta

* Exemplo: calculadora

#+BEGIN_SRC python
@tool
def calculate(a: float, b: float, operation: str) -> float:
    """Performs a math operation between two numbers
    and returns the exact result.
    Use when you need to do calculations.
    operation: 'add', 'subtract', 'multiply', 'divide'
    """
    ops = {'add': a+b, 'subtract': a-b,
           'multiply': a*b, 'divide': a/b}
    return ops[operation]
#+END_SRC

Parâmetros nomeados: seguro e simples. Sem =eval=, sem parsing.

* Exemplo: tamanho de palavra

#+BEGIN_SRC python
@tool
def get_word_length(word: str) -> int:
    """Returns the number of characters in a word.
    Use when the user asks about the length
    of a word or how many letters it has.
    """
    return len(word)
#+END_SRC

* O segredo: descrição clara

O modelo decide baseado na descrição.

*Descrição ruim:*
#+begin_quote
"Calculadora."
#+end_quote

→ Modelo não sabe quando usar.

#+REVEAL: split
*Descrição boa:*
#+begin_quote
"Performs a math operation between two numbers and returns the exact result. Use when you need to do calculations."
#+end_quote

→ Modelo entende quando E como usar.

* @tool: Pydantic resolve o parsing

#+ATTR_REVEAL: :frag (appear)
- =@tool= gera o schema JSON automaticamente
- Pydantic valida e converte os tipos
- ~"234" → 234.0~ (conversão automática)
- =ValidationError= se o LLM manda lixo

#+REVEAL: split

Sem =@tool=:
#+BEGIN_SRC python
a = float(args["a"])       # manual
b = float(args["b"])       # manual
#+END_SRC

Com =@tool=:
#+BEGIN_SRC python
resultado = calculate.invoke(args)  # Pydantic!
#+END_SRC

* O ciclo da ferramenta

#+HTML: <div style="text-align:center;">
#+HTML: <img src="/pages/guilda-ia/img/ciclo-ferramenta-v2.svg" style="max-width:70%;max-height:58vh;" />
#+HTML: </div>

#+ATTR_HTML: :style font-size:0.55em;
1. Você descreve as ferramentas pro LLM (nome, descrição, parâmetros)
2. O LLM lê a pergunta e *decide* se alguma serve
3. Ele devolve os *argumentos* — não a resposta
4. Python executa a função de verdade
5. O resultado volta pro LLM, que formula a resposta final

* O ciclo manual: =bind_tools=

#+ATTR_HTML: :style font-size:0.6em;
1. =invoke= → LLM *decide* (retorna =tool_calls=, não executa)
2. Você executa a ferramenta com os argumentos
3. =invoke= de novo com =ToolMessage= → resposta final

#+REVEAL: split

Passo 1 — o LLM decide:
#+BEGIN_SRC python
resposta = llm_com_ferramentas.invoke(
    "Quanto é 234 vezes 987?")
pprint(resposta.tool_calls)
# [{'name': 'calculate',
#   'args': {'a': 234, 'b': 987,
#            'operation': 'multiply'},
#   'id': 'call_abc123'}]
#+END_SRC

=resposta.content= é *string vazia* — o LLM não executou!

#+REVEAL: split

Passo 2 — você executa:
#+BEGIN_SRC python
tc = resposta.tool_calls[0]
resultado = FERRAMENTAS[tc['name']].invoke(tc['args'])
print(resultado)  # 230958.0
#+END_SRC

Passo 3 — resultado volta pro LLM:
#+BEGIN_SRC python
mensagens = [
    HumanMessage(content="Quanto é 234 vezes 987?"),
    resposta,  # AIMessage com tool_call
    ToolMessage(content=str(resultado),
                tool_call_id=tc['id']),
]
resposta_final = llm_com_ferramentas.invoke(mensagens)
# "O resultado é 230.958."
#+END_SRC

* ReAct se completa

O ciclo manual *é* ReAct em ação:

#+ATTR_HTML: :style font-size:0.7em;
- *Thought* → LLM raciocina ("preciso calcular")
- *Action* → LLM chama ferramenta (=tool_calls=)
- *Observation* → você executa e devolve o resultado
- *Answer* → LLM formula a resposta final

([[https://arxiv.org/abs/2210.03629][Yao et al., 2022]])

* E quando precisa de duas?

"Quanto é 10 mais 100 vezes 3?" não é uma conta só:

#+BEGIN_SRC text
10 + (100 * 3)   →   duas operações
#+END_SRC

O modelo pede *a primeira*, recebe o resultado, e aí pede *a segunda*.

#+REVEAL: split

O ciclo *repete* até ele ter tudo que precisa:

#+BEGIN_SRC python
while resposta.tool_calls:
    ...executa a ferramenta e devolve...
    resposta = llm_com_ferramentas.invoke(historico)
#+END_SRC

#+ATTR_HTML: :style font-size:0.6em;
Sem esse laço, a resposta final chega *vazia* — ele ainda está pedindo ferramenta.

* O ciclo automático: =create_agent=

O ciclo manual é bom pra entender. Na prática:

#+BEGIN_SRC python
from langchain.agents import create_agent

agente = create_agent(llm, [calculate, get_word_length])

resultado = agente.invoke(
    {"messages": "Quanto é 234 vezes 987?"})
print(resultado["messages"][-1].content)
#+END_SRC

Uma linha. Decide, executa, responde — tudo automático.
