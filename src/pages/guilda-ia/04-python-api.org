* Continuação: Python e APIs

Na semana passada ([[./03-python-minimo.org][Python Mínimo]]), montamos a base: variáveis, listas, dicionários e funções. E vimos a estrutura mais importante desta aula:

* O conceito universal: HTTP request/response

Toda API de LLM funciona com o mesmo padrão, chame ela do nome que chamar:

#+begin_quote
Você manda um JSON via HTTP e recebe um JSON de volta. Muda a URL, muda um detalhe do formato, mas o conceito é universal. Entender HTTP = entender *todas* as APIs de LLM.
#+end_quote

Pense num garçom: você entrega o pedido (request) e recebe o prato (response). O garçom não cozinha — ele transporta.

* Setup: Ollama

O Ollama é um servidor que roda modelos de linguagem na sua máquina. Em quatro passos:

#+BEGIN_SRC shell
# 1. Instalar (Linux/macOS)
curl -fsSL https://ollama.com/install.sh | sh

# 2. Baixar o modelo do curso (~2-3 GB, roda até em notebook simples)
ollama pull gemma4:e2b-it-qat

# 3. Conferir o que está instalado
ollama list

# 4. Conversar via terminal (teste rápido, sem código!)
ollama run gemma4:e2b-it-qat
#+END_SRC

Depois disso, o Ollama fica servindo na porta *11434*. Qualquer programa pode mandar requisições HTTP pra ~http://localhost:11434~ e conversar com o modelo.

#+begin_quote
No *Colab*, o notebook desta aula ([[https://colab.research.google.com/github/luksamuk/guilda-ia/blob/main/notebooks/aula04.ipynb][📓 abrir o Colab]]) faz o setup por você: T4 GPU, instalação e download já estão nas células. A primeira inferência demora ~2-3 min (warm up — o modelo carrega na GPU) e depois as respostas ficam rápidas.
#+end_quote

* A API nativa do Ollama: ~/api/chat~

Aqui está o *coração da aula*: ~requests~ puro, sem SDK nenhum.

#+BEGIN_SRC python
import requests

OLLAMA_URL = "http://localhost:11434/api/chat"
MODEL = "gemma4:e2b-it-qat"

def chat(messages, stream=False):
    """Envia mensagens pro Ollama e retorna a resposta."""
    payload = {
        "model": MODEL,
        "messages": messages,
        "stream": stream,
        "keep_alive": -1,   # mantém o modelo carregado
    }
    response = requests.post(OLLAMA_URL, json=payload, timeout=300)
    if response.status_code != 200:
        raise Exception(f"Erro {response.status_code}: {response.text}")
    return response

# Teste
r = chat([
    {"role": "system", "content": "Você é um assistente útil. Responda em português."},
    {"role": "user", "content": "Qual é a capital de Minas Gerais?"}
])
resultado = r.json()
print(resultado["message"]["content"])
#+END_SRC

A resposta chega em JSON — o campo ~message.content~ traz o texto do modelo:

#+BEGIN_SRC python
{
  "model": "gemma4:e2b-it-qat",
  "message": {
    "role": "assistant",
    "content": "A capital de Minas Gerais é Belo Horizonte."
  },
  "eval_count": 14
}
#+END_SRC

Repare como *a semana passada já preparou tudo*: o payload é uma lista de dicts, e a resposta também é um dict. Python puro contra um modelo rodando na sua máquina.

* Parâmetros de configuração

O modelo obedece a instruções, mas o *estilo* da resposta você controla com parâmetros:

#+BEGIN_SRC python
payload["options"] = {
    "temperature": 0.7,     # 0.0 determinístico → 1.0 criativo
    "num_ctx": 8192,        # janela de contexto (tokens)
}
#+END_SRC

| Faixa | Comportamento | Uso |
|-------+---------------+-----|
| 0.0-0.3 | Muito determinístico | Código, fatos, análises |
| 0.4-0.7 | Equilibrado | Conversa geral |
| 0.8-1.0 | Criativo | Escrita criativa, brainstorming |

* Chat com memória (multi-turno)

Cada chamada envia o *histórico completo*. O modelo não "lembra" — ele recebe toda a conversa de novo:

#+BEGIN_SRC python
historico = [
    {"role": "system", "content": "Você é um assistente útil. Responda em português. Seja conciso."}
]

historico.append({"role": "user", "content": "Meu nome é Lucas e eu amo IA."})
r1 = chat(historico)
historico.append({"role": "assistant", "content": r1.json()["message"]["content"]})
print(f"🤖: {r1.json()['message']['content']}")

historico.append({"role": "user", "content": "Qual é o meu nome?"})
r2 = chat(historico)
historico.append({"role": "assistant", "content": r2.json()["message"]["content"]})
print(f"🤖: {r2.json()['message']['content']}")   # Deve lembrar do nome!
#+END_SRC

#+begin_quote
É como repetir toda a conversa toda vez que você fala. O "contexto" do modelo é essa lista — e é ela que vamos manipular nas próximas aulas pra construir agentes.
#+end_quote

* Streaming (resposta em tempo real)

Com ~stream=True~, o servidor manda pedaços da resposta conforme gera — a mesma experiência do chat "digitando":

#+BEGIN_SRC python
response = chat([

for line in response.iter_lines():
    if line:
        chunk = json.loads(line)
        if "message" in chunk and "content" in chunk["message"]:
            print(chunk["message"]["content"], end="", flush=True)
print()

* O padrão universal: ~/v1/chat/completions~

O Ollama também expõe um endpoint *OpenAI-compatible*: ~/v1/chat/completions~. O formato nasceu na API da OpenAI e virou padrão de mercado — praticamente todo servidor de LLM fala esse dialeto.

#+BEGIN_SRC python
OPENAI_URL = "http://localhost:11434/v1/chat/completions"

payload = {
    "model": "gemma4:e2b-it-qat",
    "messages": [
        {"role": "system", "content": "Você é um assistente útil. Responda em português."},
        {"role": "user", "content": "O que é Python em uma frase?"}
    ],
    "temperature": 0.7,
    "max_tokens": 64
}

response = requests.post(OPENAI_URL, json=payload, timeout=300)
data = response.json()
print(data["choices"][0]["message"]["content"])
#+END_SRC

#+begin_quote
*Ponto-chave:* o formato é idêntico ao da OpenAI. A única diferença aqui é a URL (~localhost~ em vez de ~api.openai.com~). Isso é poderoso: *o mesmo código funciona com qualquer servidor* que fale esse dialeto.
#+end_quote

* Outros servidores: a família llama.cpp

Todo modelo de linguagem (mesmo os do Ollama) roda, lá no fundo, no *llama.cpp* — o motor de inferência open source que virou a infraestrutura do ecossistema local. O ~ollama~ é uma camada amigável em cima dele.

Quando você quer controle fino, pode subir o ~llama-server~ *direto* — apontando pra um arquivo GGUF no disco. Este exemplo roda o LFM2.5-2.6B (um modelo agêntico da Liquid AI, treinado pra usar ferramentas), com contexto de 8K tokens:

#+BEGIN_SRC shell
llama-server \
  --port 8081 \
  --model ~/.llama-models/lfm2.5-2.6b/LFM2.5-2.6B-QAD-Q4_0.gguf \
  --fit on --fit-target 512 \
  --ctx-size 8192 \
  --jinja \
  --temp 0.1 --top-p 0.9 --top-k 50 --min-p 0.0 \
  --repeat-penalty 1.1 \
  --cache-type-k q4_0 --cache-type-v q4_0 \
  --flash-attn auto
#+END_SRC

O que cada flag faz:

| Flag | Papel |
|------+-------|
| ~--model~ | O GGUF do disco (LFM2.5 quantizado Q4_0) |
| ~--fit on~ / ~--fit-target~ | Encaixa o modelo na VRAM disponível (deixa 512 MB de folga) |
| ~--ctx-size~ | Janela de contexto: 8192 tokens |
| ~--jinja~ | Usa o chat template embutido no GGUF |
| ~--temp~, ~--top-p~, ~--top-k~, ~--min-p~, ~--repeat-penalty~ | Amostragem (recomendação da Liquid AI: temp bem baixa, 0.1) |
| ~--cache-type-k/v~ | KV cache quantizado — economiza VRAM |
| ~--flash-attn~ | Flash Attention — contexto grande com menos memória |

O servidor sobe em ~http://localhost:8081~ — e aí é só apontar o mesmo código de antes:

#+BEGIN_SRC python
# O MESMO payload, trocando URL e modelo. Só isso.
response = requests.post(
    "http://localhost:8081/v1/chat/completions",
    json=payload,   # model: "lfm2.5-2.6b" (o nome é livre!)
    timeout=120
)
print(response.json()["choices"][0]["message"]["content"])
#+END_SRC

#+begin_quote
⚠️ *max_tokens folgado:* esse modelo *raciocina antes de responder* — o rascunho de pensamento entra no campo ~reasoning_content~ e consome o orçamento de tokens. Com ~max_tokens~ curto, ~content~ chega *vazio* (~200+ tokens dá folga pra uma resposta tranquila). Comportamento do modelo, não do servidor — o Ollama não separa os campos, o llama-server sim.
#+end_quote

#+begin_quote
Um código, dois servidores na mesma máquina. Ollama e llama-server falam o mesmo dialeto — e ferramentas como o *llama-swap* (na porta 12434) colocam um gerenciador na frente de vários servidores pra trocar de modelo a quente.
#+end_quote

* Tratamento de Erros

Erros são iguais com qualquer API — o padrão é ~try/except~ com retry e backoff:

#+BEGIN_SRC python
import time

def chamar_api(url, payload, timeout=30, tentativas=3):
    """Faz request com retry automático."""
    for tentativa in range(tentativas):
        try:
            response = requests.post(url, json=payload, timeout=timeout)
            response.raise_for_status()  # levanta exceção para erros HTTP
            return response.json()
        except requests.exceptions.ConnectionError:
            print(f"⚠️ Servidor fora do ar. Tentativa {tentativa + 1}/{tentativas}...")
            time.sleep(2)
        except requests.exceptions.Timeout:
            print(f"⚠️ Timeout. Tentativa {tentativa + 1}/{tentativas}...")
            time.sleep(2)
        except requests.exceptions.HTTPError as e:
            if e.response.status_code == 429:
                print("⚠️ Rate limit. Aguardando...")
                time.sleep(5)
            else:
                raise Exception(f"❌ HTTP {e.response.status_code}: {e.response.text}")
    raise Exception("❌ Número máximo de tentativas excedido")
#+END_SRC

Códigos de erro comuns:

| Código | Significado | O que fazer |
|--------+-------------+-------------|
| ConnectionError | Servidor não existe | Conferir se ~ollama serve~/~llama-server~ está rodando |
| 404 | Modelo não encontrado | Conferir o nome listado em ~/api/tags~ |
| 401 | Não autorizado | Servidor exigindo auth (raríssimo em local) |
| 429 | Rate limit | Aguardar e tentar novamente |
| 500 | Erro no servidor | Conferir payload; tentar de novo |

#+begin_quote
No mundo local, o erro mais comum não é 401 nem 429 — é *ConnectionError*: você esqueceu de subir o servidor antes de fazer a requisição.
#+end_quote
